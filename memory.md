## Decisions made

**Token architecture is two-layer.** The Kestrel palette (`--bg`, `--fg`, `--accent`) is what a buyer edits; shadcn's semantic layer (`--primary`, `--muted`, `--ring`) maps onto it in `globals.css`. Consequence: shadcn components inherit the design with **no per-component retokenization**. `button.tsx` is unmodified in that respect and renders violet in both themes.

**One trap in that mapping:** shadcn means "neutral hover surface" by `--accent`; Kestrel means "brand violet". Any future shadcn component using `bg-accent` must be swapped to `bg-surface-raised` on add. Currently added components are unaffected.

**`:root` = light, `.dark` = dark**, following the shadcn/next-themes convention. Dark is still the designed-first palette and the default. Inverting this (which the context files originally specified) silently breaks every `dark:` variant shadcn ships.

**`--chart-1: var(--accent)`** so the dashboard mockup rebrands with the accent. `--chart-2` through `--chart-5` stay independent — supporting series must remain visually distinct.

**shadcn installed the `base-nova` style, built on `@base-ui/react`, not Radix.** Verify component APIs against Base UI docs. Base UI uses a `render` prop where Radix uses `asChild`.

**Fonts come from the `geist` package, not `next/font/google`** — self-hosted, no runtime dependency on Google Fonts, works offline, OFL so redistribution is clear. Font licensing matters here because the template is resold.

**No chart library.** Mockup charts are hand-written SVG/flex with geometry computed from `lib/mock-dashboard.ts`, so editing a value redraws the chart.

**No stock photography and no imitation brand logos.** Testimonial avatars are initials; logo-cloud marks are geometric SVG. Both because the companies are fictional and the buyer would be shipping the implication under their own brand.

**Annual pricing is always derived** (`monthlyPrice * 12 * multiplier`), never stored.

**`enableSystem={false}`** — dark is the marketplace-screenshot look and should not be overridden by a visitor's OS preference.

## Problems solved

**Base UI Button stripped button semantics.** `nativeButton` defaults to `true`, so rendering a `Link` through `render` logged an error and removed button semantics — an accessibility defect that would have shipped on every CTA. Fixed once in `components/ui/button.tsx`: `nativeButton` now defaults to `false` when a `render` prop is passed.

**lucide-react v1 removed every brand icon** (`Github`, `Linkedin`, `Twitter`). Brand marks are now inline SVG in `components/brand/SocialIcon.tsx`. Also **`Filter` was renamed `Funnel`** — caught before feature 07 would have hit it.

**Rebrand promise was false for charts.** Editing `--accent` did not change the dashboard because `--chart-1` was its own literal. Fixed. **Test rebranding by editing `globals.css`, never by injecting CSS variables at runtime** — runtime injection does not repaint `bg-primary` in the dev server and produces false failures.

**Bar chart rendered labels but no bars** — `items-end` on the flex parent collapsed column height so the inner `flex-1` had nothing to fill.

**Switch touch target was under 44px.** Stock shadcn gives 55×34; changed `after:-inset-y-2` → `after:-inset-y-[14px]` for 55×45. Note `getBoundingClientRect` does not measure the `::after` hit area — probe `elementFromPoint` outward from the centre instead.

**Bento grid left a hole** — feature spans must total a multiple of 3. Currently 9.

**Three browser-pane artifacts that cost real time.** Before trusting any measurement, assert `window.innerWidth > 0` and check `document.visibilityState`:
1. `window.scrollTo()` changes position without firing scroll events — dispatch the event manually to test scroll-driven UI.
2. Synthetic `left_click` does not reach Base UI components — use `element.click()` or a full `pointerdown → mouseup → click` sequence.
3. The pane can collapse to `innerWidth: 0`, making all geometry meaningless. A hidden document also throttles rAF, which stalls CSS animations and leaves Base UI transition markers (`data-starting-style`) stuck — this produced a convincing but entirely false "accordion is broken" investigation.

**`create-next-app` exits 0 while failing** on an invalid directory name. Do not trust its exit code.

## Current state

**Working:** the complete home page — hero, coded dashboard mockup, logo cloud, feature bento, how-it-works, testimonials, pricing with working monthly/annual toggle, FAQ accordion, CTA band, footer. Both themes correct. Responsive 375px → 1440px with no horizontal overflow. `npm run build` passes with zero errors and zero warnings. Zero console errors in a fresh tab.

`lib/validate-config.ts` warns in development about invariants TypeScript cannot express (tier count, exactly-one-highlighted, span totals). Verified by deliberately breaking it.

**Dev server** runs on port 3000, logging to `/tmp/kestrel-dev.log` (needed to read the config validator's server-side warnings).

**Not built:** features 12–23 — pricing page, blog index, MDX pipeline, changelog, 404, motion pass, forms, SEO, QA passes, docs, deployment.

**Known temporary:** `app/tokens/page.tsx` is an internal token reference with a DELETE BEFORE SHIPPING banner and `robots: noindex`. It is useful through the theme QA pass in feature 20 but **must be removed in feature 22** — neither the banner nor noindex stops it shipping in the buyer's zip.
